# Проверяем email-рассылку до загрузки в UniSender

**UniSender campaign kit** — бесплатный офлайн-инструмент для подготовки рассылки
в UniSender **Classic**. Дайте агенту черновик письма, реестр разрешений и список
исключений. Получите проверяемый разбор: какие строки проходят заданные правила,
какие исключены и почему. Без подключения кабинета, API-ключей, импорта базы и
отправки писем.

[English guide](README.md) ·
[Lookatshow: система и открытые инструменты](https://github.com/ilookatshow-gif/lookatshow-open-tools)

## Сначала попробуйте на учебном примере

Нужен **Python 3.9+**, дополнительные библиотеки не нужны. В распакованной папке:

```sh
python3 -B lookatshow_mail_plan.py doctor
python3 -B lookatshow_mail_plan.py demo
```

На Windows используйте `python` или `py -3`, если так называется ваш интерпретатор.
Демо берёт только вымышленные адреса из домена `example.invalid`. Время проверки
зафиксировано: **14 октября 2026 года, 17:00 МСК**. Вашу почту оно не читает.

| Учебная строка | Результат | Причина |
| --- | --- | --- |
| 1 | Проходит локальные правила | Указаны положительный флаг разрешения, дата и ссылка на доказательство; в переданных данных нет исключения. |
| 2 | Исключена | Повтор первой строки после нормализации адреса. |
| 3 | Исключена | Адрес есть в переданном списке исключений. |
| 4 | Исключена | Указанный срок разрешения закончился. |
| 5 | Исключена | Указано, что человек отписался. |
| 6 | Исключена | Положительного флага разрешения нет. |

Итого: **6 строк, 5 уникальных адресов с допустимым синтаксисом, 1 строка проходит
локальные правила, 5 исключены**. В `reason_counts` — причины, в `rows` — номера
строк исходного CSV. Самих адресов, текста доказательств, тела письма, путей к
файлам и рекламных вставок в обычном JSON нет. Но номера строк тоже нужно хранить
закрыто, если по исходному CSV можно восстановить людей.

**«Проходит правила» не означает «можно отправлять».** Поля
`consent_evidence_verified`, `legal_permission_verified`,
`provider_acceptance_verified`, `deliverability_verified` и `sending_performed`
остаются `false`. Программа проверяет переданные утверждения, а не достоверность
согласия, юридическую допустимость базы, готовность провайдера или доставку во
входящие. Учебные цифры не являются результатами клиентской рассылки.

## Установка без изменений системы

В распакованном пакете выберите отдельную папку установки:

```sh
python3 -B install.py --prefix "$HOME/.local/lookatshow-mail-plan-kit"
python3 -B "$HOME/.local/lookatshow-mail-plan-kit/bin/lookatshow-mail-plan" doctor
python3 -B "$HOME/.local/lookatshow-mail-plan-kit/bin/lookatshow-mail-plan" demo
```

Установщик копирует только CLI, три учебных файла, LICENSE и NOTICE.md в
`share/lookatshow-mail-plan/0.1.0/`, создаёт `bin/lookatshow-mail-plan`. Он не ходит
в сеть, не меняет PATH и файлы запуска оболочки. Папка установки должна быть новой
или пустой. Занятые пути программы и данных, непустая папка и символические ссылки
отклоняются. Существующие файлы не перезаписываются.

Запускной файл — **Python-файл без расширения**, не Windows `.exe` и не `.cmd`.
В PowerShell вызывайте интерпретатор явно:

```powershell
python -B install.py --prefix "$env:LOCALAPPDATA\LookatshowMailPlanKit"
python -B "$env:LOCALAPPDATA\LookatshowMailPlanKit\bin\lookatshow-mail-plan" demo
```

Это рецепт запуска, а не квитанция успешной проверки на Windows. Прогоните тесты
в своей среде: переносимый код и описание CI сами по себе не доказывают успешный
запуск. Дополнительная инструкция для агента остаётся в исходном пакете;
установщик не регистрирует её глобально в Codex или Claude.

Удаление: через файловый менеджер удалите **только выбранную папку установки**.
Состояние необязательного приветствия хранится отдельно; его выбранную папку тоже
можно удалить. Не удаляйте родительские `.local`, домашнюю папку или весь рабочий
проект. Реальные исходные файлы держите отдельно и закрыто.

## Проверка своих локальных файлов

Не загружайте настоящие базы и отчёты в публичные репозитории и скриншоты. Из папки
исходников тот же учебный расчёт можно воспроизвести явными командами:

```sh
python3 -B lookatshow_mail_plan.py validate --campaign examples/campaign.example.json
python3 -B lookatshow_mail_plan.py plan --campaign examples/campaign.example.json --contacts examples/contacts.example.csv --suppression examples/suppression.example.csv --at 2026-10-14T17:00:00+03:00
```

Для своей проверки замените три пути на закрытые локальные файлы и укажите
фактическое время оценки. Время обязательно содержит смещение UTC или `Z`:
программа не угадывает часовой пояс. Повтор `demo` завтра использует прежний
учебный момент, а не проверяет актуальность реальной базы.

### Черновик письма: JSON

Принимаются ровно пять полей:

```json
{
  "sender_email": "sender@mail.example.invalid",
  "sender_name": "Synthetic demonstration only",
  "subject": "Synthetic offline campaign",
  "html_body": "<p>Учебный пример.</p><a href=\"{{UnsubscribeUrl}}\">Отписаться</a>",
  "list_id": 1
}
```

`list_id` — положительное целое число, не boolean. Синтаксис email проверяется
консервативно, только ASCII; существование адреса и подтверждение отправителя не
проверяются. Неизвестные поля, повторные JSON-ключи, пустые заголовки, переносы
строк в заголовках и некорректный JSON отклоняются.

Подстановка отписки должна занимать **весь href ссылки**:
`href="{{UnsubscribeUrl}}"`. Одного токена в тексте или HTML-комментарии, ссылки с
приписанными UTM либо повторным атрибутом `href` недостаточно. Очевидно пустые или
неактивные ссылки тоже отклоняются. Но это небольшая синтаксическая проверка, не
рендер HTML/CSS и почтового клиента, аудит доступности, полный парсер шаблонов
UniSender или просмотр письма средствами провайдера.

### Реестр разрешений: CSV

Формат UTF-8. Обязательные колонки: `email`, `consent`, `consent_at`,
`consent_evidence`, `unsubscribed`. Необязательная: `consent_expires_at`.
Неизвестные или повторные колонки, разное количество ячеек и ошибочный CSV
отклоняются.

| Поле | Правило инструмента, не параметр API провайдера |
| --- | --- |
| `email` | Консервативная проверка синтаксиса, дедупликация без учёта регистра. Она может с запасом объединить адреса, для которых регистр важен. |
| `consent` | Только `true` или `false`. `yes`, `1`, пустота и догадки не принимаются; пройти может только `true`. |
| `consent_at` | ISO-время с часовым поясом, не позже `--at`. |
| `consent_evidence` | Непустая указанная вами ссылка или идентификатор доказательства, до 2 048 символов. Содержимое доказательства программа не запрашивает и не проверяет. |
| `consent_expires_at` | Необязательно. Если заполнено — ISO-время с поясом, позже согласия и строго позже `--at`. |
| `unsubscribed` | Только `true` или `false`. `true` исключает строку независимо от флага согласия. |

У одинаковых нормализованных дублей сохраняется первая подходящая строка,
следующие исключаются. Если у одного адреса противоречат записи о разрешении,
исключаются **все** его строки. Исправлять нужно исходные доказательства, а не
флаги ради красивого отчёта.

### Список исключений: CSV

Обязательная колонка `email`, необязательная `reason` — её содержание не выводится.
Каждый корректный адрес из списка исключается. Файл только с заголовком означает
явно переданный пустой **локальный** список; он не доказывает отсутствие исключений
в кабинете. Ошибочный адрес в списке останавливает **весь расчёт**: состав
исключений становится неопределённым.

Ограничения инструмента: до 10 MiB на входной файл, консервативно до 5 000 000
байт UTF-8 для тела HTML, до 100 000 строк данных в каждом CSV. Это защитные
ограничения, не проверка размера всего MIME-письма и не подтверждение того, что
UniSender примет сообщение.
У строки бывает несколько причин исключения; сумма причин может превышать число
исключённых строк.

## Что проверить перед отдельной реальной рассылкой

В пакете **нет команд работы с провайдером**. По официальным источникам,
проверенным 15 октября 2026 года:

- [Антиспам-политика UniSender](https://www.unisender.com/ru/antispam/)
  требует предварительного разрешения и устанавливает условия double opt-in и
  другие требования. Статус `active`, API-флаг и успешный локальный отчёт не
  создают согласие. Купленная и спарсенная база не становится допустимой.
- [createEmailMessage](https://www.unisender.com/ru/support/api/messages/createemailmessage/)
  создаёт черновик, не подтверждает отправку. Аккаунт, подтверждённый отправитель,
  доменная аутентификация, текущий список и исключения аккаунта/списка нужно
  проверять отдельно по актуальным данным.
- [createCampaign](https://www.unisender.com/ru/support/api/messages/createcampaign/)
  без `start_time` может немедленно начать отправку. Это не автоматическое
  продолжение плана. Неопределённый ответ сначала сверяют, а не повторяют вслепую.
  Описанный в документации `count=0` не является числом доставок или охватом.
- [Ссылка отписки](https://www.unisender.com/ru/support/subscribing-and-unsubscribing/unsubscribing/add-unsubscribe-link/)
  не работает в тестовых письмах провайдера. Локальная проверка подстановки тоже
  не доказывает её работу. Реальная тестовая отправка требует отдельного поручения.

Classic и UniSender Go — разные продукты. Правила меняются: перед отдельно
порученной работой с кабинетом перечитайте первоисточники. Инструмент не является
юридической консультацией или сертификацией законности базы и не обновляет статусы
контактов из UniSender.

## Команды и проверки

| Команда | Что делает |
| --- | --- |
| `doctor` | Проверяет Python и сообщает офлайн-границы; без ключей и сети. |
| `demo` | Повторяет помеченный учебный пример из шести строк. |
| `validate --campaign PATH` | Проверяет формат черновика, не выводя содержимое. |
| `plan --campaign PATH --contacts PATH --suppression PATH --at ISO_TIME` | Читает локальные данные, возвращает номера строк, количества и причины исключения. |
| `onboard --state-dir PATH` | Необязательное приветствие автора один раз на выбранную папку состояния. |

Обычный вывод — JSON; можно явно указать `--json`. `--help` — человекочитаемый.
Код возврата `0` означает, что операция завершилась, **а не что все строки прошли**.
`2` — известная ошибка проверки или безопасный отказ; `3` — непредвиденная локальная
ошибка. Ошибки не повторяют введённые адреса, HTML и пути. Экспорта получателей,
очереди отправки, cron, загрузчика ключей, телеметрии и произвольных вызовов API нет.
Только `onboard` создаёт маленький локальный маркер. Обычные команды не сохраняют
отчёты на диск, если вы сами не перенаправите вывод. Если после приветствия
`onboard` завершился с ошибкой, проверьте его локальное состояние и stderr перед
повтором: показ текста и запись маркера не являются одной атомарной операцией.
Блокировка после прерывания процесса автоматически не снимается.

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты используют вымышленные данные и проверяют в том числе отказы и чистую
установку. Прочитайте и выполните их сами: написанная здесь команда не является
квитанцией успешного CI.
